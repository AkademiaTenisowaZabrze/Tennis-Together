Tennis Together

Aplikacja do organizowania wspólnych wyjazdów rodziców i zawodników na turnieje tenisowe — dopasowania na przejazdy, noclegi i grupy wyjazdowe. Testowana obecnie wewnętrznie w Akademii Tenisowej Zabrze, na danych fikcyjnych.

Opis

Tennis Together rozwiązuje jeden konkretny problem: koszt i organizację wyjazdów na turnieje — wspólne przejazdy, wspólne noclegi, grupy wyjazdowe na dany turniej. Rodzic zgłasza wyjazd zawodnika na turniej, a aplikacja pomaga znaleźć innych jadących w tę samą stronę, w tym samym terminie.

✓ Multi-tenant od pierwszego dnia

Jedna wspólna baza danych obsługuje dowolną liczbę rodzin/klubów — dodanie kolejnych testerów albo klubów nie wymaga żadnej zmiany w architekturze, tylko więcej kont.

Architektura

Aplikacja to React SPA opakowane w Capacitor (Android + przeglądarka/PWA). Nie ma własnego backendu — logowanie, baza danych, reguły dostępu i pliki obsługuje w całości Supabase. Jedyne dwa zewnętrzne punkty kontaktu to publiczne API projektu-siostry (rankingi PZT) i codzienny import kalendarza turniejów.

Aplikacja React (Vite + Capacitor) │ ├──▶ Supabase (Postgres + Auth + Storage), region Frankfurt │ • RLS na każdej tabeli — właściciel widzi/zmienia │ tylko swoje dane │ • funkcje SECURITY DEFINER dla uzasadnionych wyjątków │ (panel trenera, dopasowany współpasażer, zawieszenie │ konta) — nigdy nie otwierają całej tabeli │ • Storage: zdjęcia profilowe (bucket "avatars") │ ├──▶ Backend PZT (FastAPI, projekt "NOWA APLIKACJA PZT │ ANDROID", Railway) — wyszukiwarka turniejów po │ zawodniku, weryfikacja loginu PZT (live scrape │ portal.pzt.pl) │ └──▶ GitHub Actions (cron, codziennie) • import kalendarza OTK (scraper PZT) i Tennis Europe wprost do tabeli `tournaments`

Model danych i bezpieczeństwo

Każda tabela ma włączone Row Level Security — domyślna reguła to „widzisz i zmieniasz tylko to, czego jesteś właścicielem”. Wyjątki (np. trener widzący zawodników swojego klubu, dopasowany współpasażer widzący czyjeś imię i zdjęcie) są zawsze realizowane przez dedykowaną funkcję SECURITY DEFINER, która zwraca dokładnie te pola, które mają być widoczne — nigdy nie otwiera całej tabeli.

Zaufanie między nieznajomymi sobie rodzinami

Aplikacja kojarzy rodziny, które się wcześniej nie znały, do wspólnego przejazdu czy noclegu — z udziałem dzieci. Trzy niezależne, celowo lekkie warstwy budują zaufanie bez pełnej weryfikacji tożsamości (dokument tożsamości i formalna weryfikacja są odłożone do etapu z udziałem prawnika):

1
Weryfikacja zawodnika przez login PZT

Imię i nazwisko z profilu porównywane live z bazą Polskiego Związku Tenisowego — zewnętrzna, trudna do sfałszowania kotwica tożsamości zawodnika.

2
Potwierdzenie spotkania kodem/QR

Po zaakceptowaniu przejazdu/noclegu jedna strona pokazuje 6-znakowy kod (i QR), druga wpisuje go na miejscu spotkania — potwierdza, że to naprawdę ta osoba z ustalenia.

3
Opcjonalne zdjęcie profilowe

Widoczne wyłącznie dla dopasowanej drugiej strony po akceptacji — pomaga rozpoznać się na miejscu, nie jest weryfikacją tożsamości.

Schemat bazy danych

Wszystkie zmiany schematu żyją jako kolejno numerowane pliki SQL w supabase/migrations/ — uruchamiane ręcznie w Supabase SQL Editor (projekt nie ma jeszcze zautomatyzowanego wdrażania migracji). Każdy plik tłumaczy w komentarzu, co i dlaczego zmienia.

Czego celowo nie ma (jeszcze)

  • Regulamin i polityka prywatności — w przygotowaniu z prawnikiem; dopóki ich nie ma, aplikacja testowana tylko wewnętrznie, na danych fikcyjnych.
  • Prawdziwe płatności — mechanizm zawieszania konta (accounts.status + RLS) jest gotowy, ale podłączenie realnego operatora płatności to osobny, przyszły krok.
  • Panel administratora — moderacja dziś tylko przez bezpośrednie zapytania SQL w Supabase.
  • Wbudowany skaner QR — potwierdzenie spotkania działa przez ręczne wpisanie kodu (zeskanowanego zwykłym aparatem telefonu), nie przez kamerę wbudowaną w aplikację.
  • Weryfikacja numeru telefonu (SMS) — wymagałaby płatnego dostawcy SMS; niepodjęta, dopóki nie będzie wyraźnej potrzeby.
  • Nocleg u rodziny innego zawodnika — odłożony do etapu z pełną weryfikacją tożsamości i konsultacją prawną.
